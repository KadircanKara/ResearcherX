I am building an web product for research where users can conduct academic research on topics through an interactive continuous chat flow like chatgpt. However, it will also include an assistant mode for mostly daily tasks where I will integrate messaging channels like WhatsApp, Telegram, Email and LinkedIn. Users will be able to connect multiple email accounts but only one for every other channel I just mentioned. Research service will have a Projects tab and each project will have a pointer (reference) so that users can feed the context of certain projects anywhere (chat section in assistant mode and research mode, message drafting, etc.). Message drafting means giving AI instructions to draft a message via any messaging channel. App will also have a linkedin post generating capabilities where the projects can be referenced as well (User gets to linkedin post generator tool -> References a project -> Gives a prompt so that AI generates a post considering the instructions in the prompt including tone, length, etc.). We will also have sharing capabilities in projects where users can share their academic research with other users.

Vision for Research Tool:
Everything will be done inside a project. If the user wants to research something without creating a project, he/she will have to do so from the assistant section of the app. However, he/she will have the option to copy chat(s) from the assistant section over to any project. So inside each project:
- User explains what he is researching (e.g. AI methods in multi-UAV systems)
- Relevant papers get displayed with initial analysis on what is missing and what matches the user's prompt (e.g. Included: Multi-UAV Systems Not Included: AI Methods) with the option to "Add to Graph".
- "Graph" is the page where each paper added to the "graph" is connected like branches on a tree. Paper 1 -> Paper 2, Paper 1 -> Paper 3, Paper 4 may not be connected to any other paper, ... connections like that where each related paper can be connected. Graph will have a filtering section where papers can be excluded from the graph to focus on a subset of all papers in the full inclusive graph. When a user clicks on a paper in the graph page, a panel will open up on the right side with paper view, connected papers, paper summary, connections tabs. First three tabs are self-explanatory and in the last tab, all the nodes in the graph page can be toggled and the user will be able to generate a connection analysis between the toggled papers.
- Paper Editor page is the page where LaTeX code will be written for academic papers. It will have share functionality between users with permission levels (edit, view, owner). There will be an option to compile latex code, download pdf, comment section where users can be tagged with "@". Also, drafting messages with AI will be available in this page as well (e.g. Draft a reminder for "@user1" and "@user2" that this and that change will need to be made on March 15th the latest).

That is my vision for this app so far. Get busy :)
